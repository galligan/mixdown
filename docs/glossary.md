# Glossary of Mixdown Terms

This glossary defines key terms used within the Mixdown project and documentation.

## Alias

An "alias" is a key-value pair defined in `.mixdown/config.yaml` that can be used to expand its value when an [include](#include) is used (e.g., `$[alias:my-alias]` expands to the configured value). Aliases can reference other includes, including [profile](#profile) data.

## Artifact

An "artifact" is a concrete file generated by Mixdown from a [mix](#mix) for a specific target tool. Examples include `.mdc` files for Cursor Rules, CLAUDE.md for Claude Code, etc. Artifacts are typically stored in the `prompts/artifacts/builds/{build_id}` directory.

## Build

A "build" is the process (mixdown build command) of compiling [mixes](#mix) into [artifacts](#artifact) for the configured target tools. Each build generates a unique set of artifacts stored in a directory within `prompts/artifacts/builds/`.

## Data (serialized data files)

YAML-formatted files (`*.profile.yaml` or `*.data.yaml`) stored in `prompts/includes/` containing structured data (e.g., user details, project info, organizational standards). This data can be injected into mixes using include syntax (e.g., `$[profile:user.name]`, `$[data:project.api_key]`).

## Include

An "include" is a mechanism (`$[include:...]` syntax) used within a mix to inject content from another source. Sources can be files from `prompts/includes/`, `prompts/instructions/`, `prompts/templates/`, specific file paths, or runtime variables (`$[include:@...]`).

## Instruction

A specific directive or piece of guidance provided within a [mix](#mix), often within `<instructions>` tags, intended for an AI model or agent. Also refers to the `prompts/instructions/` directory where source mix files are stored.

## Meta

The YAML frontmatter-formatted section of a mix, which contains configuration data such as the mix's name, description, and any other relevant metadata.

## Mix

A "mix" is the source file (`.mixd` extension) containing the primary instructions, structure, and metadata. It acts as the template or "gold master" from which artifacts are generated, which become tool-specific files for rules, modes, instructions, etc. Mixes combine XML structure, Markdown content, YAML frontmatter (`<meta>`), [placeholders](#placeholder), [includes](#include), [segments](#segment), and [overrides](#override).

## Override

An "override" (`<override>` tag) is used within a mix to provide tool-specific content or metadata that applies only when generating artifacts for the specified tool(s).

## Placeholder

A "placeholder" (`[this is a placeholder]` syntax) is a token within a mix that instructs an AI model or agent to fill in a specific value (e.g., `[title]`, `[date format="YYYY-MM-DD"]`).

## Profile

See [Data](#data).

## Provider (Plugin)

A "provider" (often referred to as a plugin, typically packaged as `@mixdown/plugin-{provider-name}`) is a distinct software component responsible for rendering a mix's Abstract Syntax Tree (AST) into the specific format required by a target tool (e.g., Cursor, Claude Code). Providers define how artifacts are named, structured, and where they are written. They are sometimes referred to as "tools."

## Segment

A "segment" (`<segment>` tag) is a named block of content within a mix that can be conditionally included in the main artifact or exported (`export="tool"`) as a separate artifact file for specific tools. Segments allow for modularity and tool-specific structuring of instructions.

## Template

A file (`.template.mixd` extension) stored in `prompts/templates/` that defines a reusable structure or format, often used for generating specific types of output like reports or plans. Templates can be injected into mixes using $[include:template:name].
