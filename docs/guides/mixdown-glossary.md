# Glossary of Mixdown Terms

This glossary defines key terms used within the Mixdown project and documentation.

## Alias

An "alias" is a key-value pair defined in `.mixdown/config.yaml` that can be used to expand its value when referenced using the `{@name}` syntax (e.g., `{@my-alias}` expands to the configured value). Aliases can reference other includes, including [profile](#profile) data. Alias resolution follows a specific order: mix's frontmatter → project private aliases → project public aliases → global aliases.

## Artifact

An "artifact" is a concrete file generated by Mixdown from a [mix](#mix) for a specific target tool. Examples include `.mdc` files for Cursor Rules, CLAUDE.md for Claude Code, etc. Artifacts are typically stored in the `prompts/artifacts/builds/{build_id}` directory.

## Build

A "build" is the process (mixdown build command) of compiling [mixes](#mix) into [artifacts](#artifact) for the configured target tools. Each build generates a unique set of artifacts stored in a directory within `prompts/artifacts/builds/`.

## Data (serialized data files)

YAML-formatted files (`*.profile.yaml` or `*.data.yaml`) stored in `prompts/data/` containing structured data (e.g., user details, project info, organizational standards). This data can be injected into mixes using data placeholder syntax (e.g., `{=user.name}`, `{=project.api_key}`).

## Frontmatter

The YAML-formatted section at the beginning of a mix file, enclosed by `---` delimiters, which contains configuration data such as the mix's name, description, target specifications, and any other relevant metadata. Frontmatter replaces the previous `<meta>` tag approach.

## Include

An "include" is special mix file located in `prompts/instructions/includes` which are used as injectable content for mixes. You can think of them as snippets of code or instructions that can be reused across mixes. Includes are referenced using [mixins](#mixin) with the `{{$my-include}}` syntax.

## Instructions Directory

The `prompts/instructions/` directory contains the following subdirectories:

- `mixes/`: Markdown files used as the basis for artifacts to be built.
- `includes/`: Special mix-formatted files used as injectable content for mixes.
- `templates/`: Templates for generating specific types of output like reports or plans.

## Mix

A "mix" is the markdown-formatted source file containing the primary instructions, structure, and metadata. It acts as the template or "gold master" from which artifacts are generated, which become tool-specific files for rules, modes, instructions, etc. Mixes combine Markdown content, YAML frontmatter, [placeholders](#placeholder), [mixins](#mixin), [sections](#section), and target-specific overrides.

## Mixin

A "mixin" is a mechanism to include another mix, include, or template inline using the `$` sigil within a section delimiter (e.g., `{{$include:my-include}}`, `{{$mix:common-rules}}`). Mixins support attributes like `as`, `no-title`, `no-embeds`, and `include-frontmatter` to control how the embedded content is rendered.

## Override

Target-specific overrides allow customizing content or attributes for specific targets. These can be applied using the `@target` syntax for attributes (e.g., `title@cursor="Cursor Rules"`) or in the frontmatter by adding target-specific sections.

## Placeholder

A "placeholder" is a token within a mix that is replaced with specific content during the build process. They fall under one of two categories:

### Static Placeholders

- Static placeholders for AI: `[ fill this in ]`

### Dynamic Placeholders

- Alias placeholders: `{@name}`
- Data placeholders: `{=user.name}`
- Internal links: `{>file#section|Alias}`

## Profile

See [Data](#data). Referenced using data placeholders with the `{=name.property}` syntax.

## Provider (Plugin)

A "provider" (often referred to as a plugin, typically packaged as `@mixdown/plugin-{provider-name}`) is a distinct software component responsible for rendering a mix's Abstract Syntax Tree (AST) into the specific format required by a target tool (e.g., Cursor, Claude Code). Providers define how artifacts are named, structured, and where they are written.

## Section

A "section" (enclosed in `{{name}}...{{/name}}` delimiters) is a named block of content within a mix that can have attributes controlling how it's processed during build. Sections can have attributes like `id`, `title`, `export`, `filter`, etc., and can be target-specific using the `@target` suffix.

## Target

A "target" is a specific tool or platform that Mixdown builds artifacts for, such as Cursor, Claude Code, or Roo Code. The term "target" replaces the previous term "tool" in attribute assignments.

## Target Group

A "target group" is a collection of related targets that can be referenced together in filters and attributes. Built-in groups include `ide`, `cli`, `desktop`, etc. Target groups can be defined by providers or customized in the project configuration.

## Template

A file (`.template.md` extension) stored in `prompts/templates/` that defines a reusable structure or format, often used for generating specific types of output like reports or plans. Templates can be embedded into mixes using `{{$template:name}}` syntax.
